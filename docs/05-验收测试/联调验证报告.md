### 关键发现（非源码缺陷，但影响本地联调）

Redis 未启动**不只是"缓存未实测"**：用户端多个接口直接读写 `RedisTemplate` / 使用 `@Cacheable`，Redis 缺失时这些接口会报 500。实测证据：

- `GET /user/shop/status`（无 token 即可访问）→ **HTTP 500**（`ShopController` 直接 `redisTemplate.opsForValue().get`）。
- 同类受影响接口：`/user/dish/list`（`DishController` 直接读写 Redis）、`/user/setmeal/list`（`@Cacheable`）、`/user/shoppingCart/**` 与 `/user/order/submit` 链路（下单/订单号相关逻辑）、`/admin/dish/**` 与 `/admin/setmeal/**` 的写操作（缓存清理）。
- 不受影响的接口（本次已实测通过）：管理员登录、菜品分页、mockLogin、工作台统计 —— 这些走数据库、不碰 Redis。

结论：**用户若要完整走通"点餐 → 下单 → 管理端接单"，必须先启动 Redis。**

## 用户本地如何自己跑起来（交付关键步骤）

### A. 后端（IntelliJ IDEA）

1. **切到 JDK17（必须）**：本机默认 `JAVA_HOME` 指向 JDK25，Lombok 会失效导致编译报错。
   - `File → Project Structure → Project → SDK` 选 `D:\Java\jdk17`
   - `Settings → Build, Execution, Deployment → Maven → Runner → JRE` 选 **17**（或在 Maven Importing 中把 JDK 设为 17）
   - 命令行方式等价写法：`JAVA_HOME=D:/Java/jdk17 mvn -Dmaven.repo.local=D:/Study/workbuddytest/maven-repo -pl sky-server -am package -DskipTests`
2. **Maven 本地仓库（可选）**：命令行已用 D 盘仓库 `D:/Study/workbuddytest/maven-repo`；IDEA 中可在 `Settings → Maven → Local repository` 设为同路径以复用已下载依赖。
3. **启动**：运行主类 `sky-server/src/main/java/com/sky/SkyApplication.java`（右键 Run）。`application.yml` 中 `spring.profiles.active: dev` 已是 dev，无需额外配置；如需显式指定可在 VM options 加 `-Dspring.profiles.active=dev`。
4. **确认成功**：控制台出现 `Started SkyApplication`，且 8080 端口监听（浏览器访问 `http://localhost:8080/user/user/mockLogin` 用 POST 调用可返回 JSON 即通）。

### B. Redis（用户端点餐链路前置条件）

1. 启动本机 Redis 服务，监听 **6379**。
2. 确认 Redis 访问口令与 `sky-server/src/main/resources/application-dev.yml` 中 `sky.redis.password` **一致**，且 database 索引与配置一致（配置中指定的是 database 10）；口令请自行打开该文件查看，本文档不记录明文。
3. 验证：`redis-cli -h 127.0.0.1 -p 6379 -a <你的口令> ping` 返回 `PONG`。
4. 本机当前未安装 redis-server，需先安装（解压版运行 `redis-server.exe redis.windows.conf`，或安装为 Windows 服务后 `net start Redis`）。

### D. 演示账号与手机号逻辑

- **管理员**：登录页"管理员"Tab，账号 `admin`，密码为项目数据库初始化脚本中为 `employee` 表设置的默认口令（本机演示库已实测该账号可正常登录）。登录成功写入 `wl_admin_token`，跳 `/admin/dashboard`。
- **用户**：登录页"用户"Tab，输入 `user` 表中**已登记手机号**，后端按手机号查库并签发用户端 JWT（写入 `wl_user_token`），跳 `/user/home`。
- **当前演示库注意**：`user` 表仅 1 条记录（id=4）且 `phone` 为 NULL，直接输入手机号会返回"登录失败"。QA 验证时采用临时造数、测完还原，用户可照做：

  ```sql
  -- 造数（手机号可自定，需符合前端 1 开头的 11 位校验）
  UPDATE user SET phone='13800138000' WHERE id=4;
  -- 联调结束后还原（该记录原始 phone 为 NULL）
  UPDATE user SET phone=NULL WHERE id=4;
  ```

### E. 关键链路走查顺序（建议）

1. 管理员登录 → 工作台看到数据卡片（验证 `/admin/workspace/businessData`）。
2. 退出 → 用户登录（手机号按 D 节造数）→ `/user/home` 浏览菜品（**需 Redis**）。
3. 加入购物车 → 购物车页增减 → 确认订单。
4. 若提示缺少地址，先到 `/user/address` 新增地址并设为默认 → 提交订单。
5. 退出后管理员登录 → `/admin/order` 看到新订单 → 接单。
6. 回到用户端 `/user/order/list` 查看订单状态变化。
